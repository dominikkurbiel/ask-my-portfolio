# Web (Next.js)

## Stack

Next.js 16 (App Router), React 19, TypeScript (strict + `noUncheckedIndexedAccess`), TanStack Query,
API client generated by orval, Vitest, Prettier. Node 24 (`.nvmrc`), pnpm via Corepack.

## Commands (run in `web/`)

```bash
pnpm dev            # :3001, forwards /api/* to the API (API_URL, default http://localhost:8000)
pnpm api:generate   # regenerate src/lib/api/generated from ../api/openapi.json
pnpm typecheck && pnpm test && pnpm build
pnpm format
```

## API access

- **Never write `fetch` calls for regular endpoints by hand.** Use the generated functions and hooks
  from `src/lib/api/generated/` (e.g. `useGetReadiness`). Never edit generated files; change the API,
  export the schema and regenerate.
- Generated fetch functions return `{ data, status, headers }`; read `.data` and check `status` when an
  endpoint documents error responses.
- Streaming endpoints (SSE chat) are the exception: they get a small hand-written client in
  `src/lib/api/`, typed with the generated models.
- Always call relative URLs (`/api/...`): same origin, no CORS, cookies work.

## Structure

- `src/app/`: routes only (pages, layouts, providers). Keep them thin.
- `src/features/<feature>/`: components, hooks and pure logic of one feature.
- Put UI decisions in pure functions (like `describeReadiness`) and unit-test them with Vitest;
  components just render.
- Server Components by default; add `"use client"` only where state, effects or TanStack Query are needed.

## UI

- Accessible by default: semantic HTML, labels, keyboard navigation, visible focus, sufficient contrast.
- Colours and spacing come from CSS variables in `src/app/globals.css` (design tokens); no hard-coded
  colours in components.
